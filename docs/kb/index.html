What Ferrum Is

A reverse proxy sits between clients and backends: it accepts every request, decides which backend should serve it, forwards it (possibly editing headers), and relays the response — adding load balancing, health checking, caching, TLS termination, and security screening along the way. nginx, HAProxy, and Envoy are the production siblings; Ferrum is the same animal built limb by limb so every mechanism is understood rather than configured.

Analogy. The proxy is a translator sitting between two phone calls: it listens to the client call, decides who to dial on the second phone, repeats the message (possibly editing it), and repeats the answer back. It can hang up either phone independently, keep the backend line open for the next caller (pooling), or answer from memory without dialing at all (caching).

The course rule that shaped everything: zero dependencies unless hand-rolling is dangerous. Only two exceptions were ever granted — regex (Level 2, and its no-backtracking guarantee quietly became a security property two levels later) and the rustls family (Level 8, because hand-rolling crypto is the level's named mistake #1). Everything else — HTTP parsing, connection pooling, the metrics registry, the Prometheus text format, the LRU cache, the TOML config parser, the WAF — is ours, with the design arguments written into the code as teaching comments.

The Pipeline

Every request walks this path. Each stage is one level's work; the pages linked below own the details.

Build Levels (1–8)

Level 1 — Core Networking

TCP accept loop, HTTP/1.1 parsing and body framing, forwarding, keep-alive, request-smuggling defenses. The Conn<S> generic and 16 KB windowed streaming that every later level leans on.

Level 2 — Routing

RouteTable, path matchers (exact/prefix/wildcard/regex/any), host+method filters, specificity ranking, Arc sharing. The regex dependency decision.

Level 3 — Load Balancing

Seven algorithms from round-robin to a consistent-hash ring; the RAII Lease whose Drop releases inflight counts on every exit path.

Level 4 — Health Checks

The three-state circuit breaker, passive+active feeds, exponential backoff, the prober task, and a real recovery-deadlock bug story.

Level 5 — Proxy Headers & Rewriting

XFF/X-Real-IP/XFH/XFP and why each has a different trust policy; path/Host rewriting; the protected-header guardrail; CRLF-injection hardening.

Level 6 — Middleware

The synchronous two-phase pipeline (and why not the async onion), auth with constant-time compares, the sharded token-bucket rate limiter, rejection semantics.

Level 7 — Performance

The bounded LIFO connection pool, the five-condition poolability predicate, backend deadlines — and the cross-task TOCTOU bug only a whole-branch review could see.

Level 8 — Security & TLS

rustls termination and mTLS (the one from-scratch exception), the handshake-placement DoS decision, connection limits, CIDR policy, body/header caps.

Ops Levels (10–13)

Level 10 — Observability

Hand-rolled metrics (counters, gauges, histograms, Prometheus text format), leveled error log, JSON access log with stage timings, the separate admin plane.

Level 11 — Caching

Sharded approximately-LRU store, RFC 9111 semantics, the cache key as the level's one dangerous decision, both revalidation legs, streaming tee capture.

Level 12 — Production Features

Config file lowered onto the CLI vocabulary, --validate, graceful shutdown reusing the L8 limiter as drain tracker, hot reload via one pointer swap.

Level 13 — Basic WAF

Normalize-then-match-then-score (the CRS model), IP reputation as the breaker pointed inward, detect-before-block, and the honesty checkpoint.

Theory Levels (9, 14)

Level 9 — OS Internals

epoll/kqueue, the C10K problem, the full .await→Waker→reactor path traced through Ferrum's own code, the await map, nginx as the same architecture.

Level 14 — Scalability & HA

Who balances the load balancers, the fleet state audit (don't share / share approximately / share for real), CDN integration, every level's cluster-scale reappearance.
