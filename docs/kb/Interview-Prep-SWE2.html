How To Use This Page

An SWE-2 interview rarely asks "define a circuit breaker." It asks "your service's dependency starts timing out — what do you do?" and listens for whether the breaker, the retry budget, and the health-check asymmetry come out unprompted, connected, and with trade-offs. You built all three, so the preparation here is not memorizing answers — it is practicing the retrieval path from question-shape to the thing you built.

Method. For each question: (1) say the one-sentence answer out loud, (2) name the mechanism you built and the file it lives in, (3) name the trade-off you accepted and the alternative you rejected. That three-beat structure — answer, evidence, trade-off — is what separates a mid-level answer from a junior one. The level references tell you where to reread when a retrieval fails.
Honesty rule, again. Ferrum is a teaching build. In an interview, "I built a from-scratch reverse proxy to understand X" is a strong story precisely because you can say what production systems do differently — every level page's industry section arms that sentence. Never present the teaching build as production experience; present it as depth.

Round: HTTP & Networking

1. Walk me through what happens when a client sends a request through a reverse proxy. Be precise about connections.

Two sockets, one per side; independent lifetimes (keep-alive and pooling per side); parse → route → rewrite → forward → relay. L1, index pipeline diagram.

2. How do you know where an HTTP request body ends? All the cases.

Content-Length / chunked / until-close / none — and why requests can't use until-close. L1 framing.

3. What is request smuggling and how would you prevent it in a proxy you wrote?

CL+TE disagreement between parsers; reject ambiguity at parse time, own the framing headers on re-emit. L1, L5.

4. Why must a proxy strip hop-by-hop headers? Name some.

Connection/TE/Upgrade etc. describe ONE hop; forwarding them desyncs the next. L1, L5.

5. X-Forwarded-For arrives on an inbound request. Trust it?

Append, never replace; trust only from known ranges (CDN case); key limits on the socket peer. L5, L6, L14.

6. What's the difference between no-cache and no-store? s-maxage and max-age?

no-cache = store but revalidate every use; no-store = never write; s-maxage targets shared caches and wins there. L11.

7. How does ETag revalidation actually save bandwidth? Trace both directions.

Proxy→origin If-None-Match → 304 restamps the entry (no body transfer); client→proxy 304 with no body. L11.

8. Why does Vary have to be part of a cache key, and what's the worst bug if it isn't?

Serving gzip to a client that can't read it — or one user's variant to another; the key IS the isolation boundary. L11.

9. Keep-alive vs pipelining vs connection pooling — three different things. Distinguish them.

Reuse of one client connection / multiple in-flight requests on it / a pool of warm backend connections. L1, L7.

10. When can a proxy safely retry a failed backend request?

Idempotent method AND no body bytes committed AND attempts capped — the three-gate rule; retry storms kill degraded fleets. L4, L7.

11. What status codes does a proxy itself generate, versus pass through?

400/404/408/413/429/431/502/503/504 with the exact trigger for each. L1–L8 cheat sheets.

12. TLS termination: what does the backend lose when the proxy terminates, and how do you give it back?

The client's scheme and identity — X-Forwarded-Proto as an observation (listener's scheme), never a client assertion. L5, L8.

Round: Systems Design

13. Design a load balancer. (The classic.)

You built seven algorithms; lead with RR → upgrade-on-evidence, name affinity (iphash/chash) and the inflight-count race you accepted. L3.

14. How should a system handle a dependency that starts failing? Design the full failure path.

Passive detection + active probes feeding one breaker; ejection, backoff-doubling recovery probes, flap-preventing asymmetry (down after 3, up after 2). L4.

15. Design a rate limiter. Now make it work across N instances.

Token bucket, sharded, lazy refill, keyed on socket IP; at N instances: per-instance ÷N or Redis-replicated approximate counts — exact distributed counting costs a round-trip per request. L6, L14.

16. Design an HTTP cache. What's the hardest correctness problem?

The key (route + pre-rewrite target + Vary values, full equality on collision); then the RFC semantics; then stampedes — which you can DESCRIBE as recorded debt. L11.

17. How do you deploy a config change to a proxy with zero dropped requests?

Validate wholesale off to the side, swap one Arc pointer, per-exchange snapshots; invalid config can never take the proxy down. L12.

18. How do you shut a service down gracefully? What's the deadline for?

Stop accepting → drain with Connection: close → deadline so a hung client can't hold the deploy hostage; RAII connection accounting IS the drain tracker. L12.

19. One proxy instance isn't enough anymore. Take me from 1 to N.

The whole L14 ladder: DNS → VRRP → anycast → L4-over-L7; then the state audit — what ships unchanged, what goes approximate, what needs consensus. L14.

20. Where does session affinity belong in a modern system?

Nowhere, ideally — externalize sessions (Redis/JWT) so any instance serves any user; iphash/chash is the fallback for legacy state. L3, L14.

21. What belongs in metrics vs logs vs traces? Design the observability for a proxy.

Aggregates vs events vs per-request stages; status-class labels (cardinality bomb), histograms-not-averages, request-id propagation. L10.

22. Why are histogram buckets fixed and cumulative in Prometheus? What breaks otherwise?

Fixed = comparable across scrapes; percentiles at query time from bucket counts; record O(1), cumulate at scrape. L10.

23. Design a WAF. What can it promise and what can't it?

Normalize → match → anomaly-score → detect-before-block; a speed bump not a wall — real fixes are parameterized queries; the honesty checkpoint IS the senior answer. L13.

24. Your service sits behind a CDN. What changes?

Client IP becomes a CDN node (trusted-range XFF), your cache becomes layer two (s-maxage), origin pull is a keep-alive client. L14.

25. Control plane vs data plane — what's the split and why does everyone converge on it?

Data plane stays simple and never dies on bad input (validate-and-swap); the control plane owns distributed truth; L12's reload is the data-plane half of xDS. L12, L14.

26. When do you actually need consensus (Raft/etcd)? When is it overkill?

Only exactly-once duties (leader election, cert renewal); health state and rate limits deliberately DON'T need it — the don't-share/approximate/consensus hierarchy. L14.

Round: Concurrency & Async

27. How does async I/O actually work, kernel to callback? No hand-waving.

Non-blocking read attempted first (fast path), EWOULDBLOCK → register Waker → epoll/kqueue wait → wake → re-poll resuming the state machine at the await point. L9.

28. Why did epoll solve C10K when select couldn't?

O(ready) vs O(n) per wait — 9,999 idle connections cost nothing vs cost work every time. L9.

29. Task-per-connection vs thread-per-connection vs event loop — costs of each?

Heap state machine vs stack + context switches vs hand-written state machines; Tokio = the compiler writes nginx's state machines for you. L1, L9.

30. "Never hold a lock across an await." Why, and how would you ENFORCE it?

Executor starvation + deadlock risk; enforce by making every locking fn a plain fn — .await can't appear there, so the compiler is the reviewer. L9.

31. When is a std::sync::Mutex fine in async code?

Short critical sections never crossing await — the sharded limiter/cache/reputation pattern; tokio::sync::Mutex is for holding across awaits, which we never need. L6, L9, L11.

32. How do you share config across 10k concurrent tasks with zero locks on the hot path?

Arc snapshots; readers clone under a nanosecond read lock (or arc-swap); old config frees when the last holder drops — ownership solves the torn-read problem. L2, L12.

33. Two threads increment a Relaxed atomic counter. Can increments be lost? What DOESN'T Relaxed guarantee?

RMW never loses increments; Relaxed gives no cross-variable ordering — a scrape sees torn snapshots, which metrics tolerate by design. L10.

34. How do you shut down a background task without a kill channel?

Hand it a Weak; upgrade per tick; the failed upgrade IS the signal — lifetime tied to the data it serves. L12.

35. What's a TOCTOU race? Give one from real experience and its fix.

The pooled connection that died between checkout and first write — fixed by making the head-write retriable exactly like a connect failure. L7.

36. Why is one accept loop enough for thousands of connections, and what must NEVER run inside it?

It only dequeues + spawns; anything slow (a TLS handshake!) stalls every new client — one ClientHello byte = total DoS. L1, L8.

37. RAII beyond memory: give three resource types you'd manage with Drop and why.

Inflight counts (lease), limiter slots, connection gauges — many exit paths, one release point; cleanup you can't forget. L3, L8, L10.

Round: Security

38. Where does a TLS handshake belong architecturally, and what's the DoS if you get it wrong?

Inside the per-connection task with a deadline; in the accept loop, one stalled handshake blocks every new connection process-wide. L8.

39. mTLS: what does each side prove, and what are the three sane server postures?

Client certs verified against a CA; off/optional/required — and the config incoherencies to reject at boot. L8.

40. Why do WAFs normalize before matching? Walk %252e%252e%2f through your normalizer.

Evasion is encoding games; two decode passes, the changed second pass IS double-encoding and scores on its own. L13.

41. Why anomaly scoring instead of blocking on any signature hit?

O'Brien buys coffee: a lone quote is ambient noise; scoring is the difference between a WAF and a false-positive generator ops disables. L13.

42. Why must a WAF's error page never name the rule that fired?

It's a payload-tuning oracle — the attacker binary-searches your ruleset; hits go to logs only. L13.

43. Log injection: the classic attack and the JSON-era upgrade.

CRLF forged whole lines; in JSON logs an unescaped quote forges FIELDS and a control byte hides the line from jq entirely. L6, L10.

44. Timing attacks on credential checks — the bug and the fix.

Early-exit comparison leaks prefix length; constant-time compare over both full buffers. L6.

45. Why key rate limits and reputation on the socket IP instead of X-Forwarded-For?

XFF is client-controlled: unlimited throughput via random values, plus poisoning any victim's bucket. Three levels made this same choice. L5, L6, L13.

46. Slowloris: the attack, and every layer you must defend at.

Slow bytes hold resources: head-read deadline, TLS handshake deadline, admin-plane deadline — the timeout moves down a layer each time you add one. L1, L8, L10.

47. Why is /metrics on a separate listener?

Route names, backend addrs, error rates = reconnaissance; the admin plane is a different socket, exposure is an explicit choice. L10.

48. Path traversal: why "canonicalize then check", and why convict the ATTEMPT even when the result is innocent?

Encoded/mixed forms defeat raw matching; you can't know how the BACKEND resolves paths, so the probe itself is the signal. L2, L13.

49. Why is Rust's regex crate refusing backreferences a SECURITY feature?

No backtracking = guaranteed linear time = catastrophic-backtracking ReDoS is inexpressible; per-request regex on user input is safe only because of it. L2, L9, L13.

Round: Debugging & Ops

50. "The site is slow." You have 30 seconds of the operator's attention. What did you instrument yesterday to answer this today?

Per-stage timings (parse/route/connect/TTFB/transfer) in the access log split "us vs them vs the network"; histograms give which percentile. L10.

51. p50 is 40ms, an average is 40ms — which user is angry and why can't the average see them?

p99's 1-in-100 (your biggest customers hourly); an average of 40ms hides 1% at 4 seconds. L10.

52. A backend hangs after accepting a request. What does your system do, second by second?

Response-head deadline fires → 504 to the client → breaker fed → ejection after threshold → recovery probes with backoff. L4, L7.

53. A latency regression affects only SOME requests. What log field splits the population?

pooled:true/false — pool misses pay connect cost; without the field the regression looks like a slow backend. L7, L10.

54. Your health endpoint shows degraded but the supervisor shouldn't restart the process. Why is /health still 200?

The PROXY is alive; a backend outage restarted into a proxy outage makes it worse — readiness of the proxy ≠ health of its backends. L10.

55. Tests pass but the binary misbehaves. Give a real class of bug that unit tests structurally can't catch.

Cross-task composition (the TOCTOU pool bug passed every per-task review) and harness bugs (the pkill that killed the proxy itself). L7, PROGRESS.

56. What's a dead-code warning good for besides tidiness?

It's a wiring detector: render_prometheus unwired, three times this course a warning exposed a missing hookup. L13 story.

57. Why do log levels exist mechanically — what must a suppressed debug! NOT cost?

A thrown-away format! allocation; check the level before evaluating args — one atomic load. L10.

58. Config drift: how does a config FILE fight it, and why are duplicate keys an error not last-wins?

One vocabulary (file lowers onto CLI), one parser per value; a duplicated key is drift in progress and last-wins is how it hides. L12.

59. Why does --validate have to run the ENTIRE boot path?

A validator that answers a different question than boot is worse than none; parse-clean-but-invalid configs (unknown upstream) must fail it. L12.

Round: Rust / Language Design

60. Generics vs trait objects on a hot path — how do you choose?

Static dispatch for the per-read hot loop (Conn<S>, two monomorphized copies); dyn for the middleware chain where flexibility wins and calls are per-request. L1, L6, L8.

61. Why is the classic O(1) LRU miserable in safe Rust, and what do production caches do instead?

Doubly-linked aliasing + mutation is what the borrow checker exists to reject (LRU aliasing bugs are real C CVEs); shard the map, approximate the recency. L11.

62. An async fn that's never awaited — what runs?

Nothing; futures are inert values until polled; no thread exists behind them. The most common async misconception. L9.

63. Why does an owned-Response middleware API force you to buffer bodies, and what did you do instead?

The onion's post-processing needs the whole body in hand; two sync passes over heads keeps 2GB downloads at 16KB of memory. L6.

64. Arc vs Weak: when is a Weak reference the CORRECT design, not a cycle-break hack?

When a task must not extend its data's lifetime — probers die with their table; the Weak upgrade failing IS the protocol. L12.

65. Where do enums beat booleans-and-options structurally?

BodyFraming, BreakerState, Lookup{Hit/Stale/Miss}, Decision — invalid states unrepresentable, match forces every arm handled. L1, L4, L11.

66. Zero dependencies as a policy: steelman it, then attack it.

For: one parser per value, no drift, you understand every byte. Against: you rewrote chrono/tracing/lru poorly — fine for teaching, wrong for a team on a deadline; the two granted exceptions (regex, rustls) show where the line is. Whole course.

Round: Behavioral / Experience

67. Tell me about a subtle bug you found. (Have three.)

The TOCTOU pooled-connection silent failure (L7); the HalfOpen recovery deadlock (L4); the pkill harness bug that killed the proxy itself (L10 verification).

68. Tell me about a time a review process caught what individual reviews missed.

The whole-branch L7 review: every task passed its own review; the composition bug (no response at all on a dead pooled connection) was invisible to any single diff.

69. Tell me about a decision you reversed and why.

L8's 403-on-denied-CIDR reversed to silent close: answering costs a TLS handshake on the attacker's behalf — the design doc said one thing, implementation evidence said another, the reversal was recorded not hidden.

70. How do you decide build-vs-buy?

The course's two exceptions are the rubric: buy when hand-rolling is DANGEROUS (crypto), build when the internals ARE the value (metrics, cache) — and know which situation you're in.

71. Tell me about scope you cut deliberately.

Cache stampede defenses, W3C traceparent, body-inspecting WAF, graceful restart — each cut with the reason recorded and the failure mode documented; cutting with receipts is the skill.

72. How do you verify your own work beyond unit tests?

Live verification against real backends every level; kill backends mid-flight; the harness is untested code and it bit three times — say that sentence in the interview.

Your Five War Stories

Behavioral rounds reward prepared narratives. These five, told with the three-beat structure (situation → mechanism → what it taught), cover most behavioral question shapes:

1. The invisible composition bug

Every per-task review passed; the whole-branch review found a request path that returned NO response. Teaches: review granularity, TOCTOU, retry semantics. (L7)

2. The breaker that couldn't recover

HalfOpen deadlock with default thresholds — found live, fixed with a regression test that drives recovery the way the prober does. Teaches: state machines, testing the path not the unit. (L4)

3. The handshake in the wrong place

One ClientHello byte could stall every connection; moving one .await changed the security posture of the whole proxy. Teaches: architecture IS security. (L8)

4. The reversal with receipts

Design said 403 on denied IPs; implementation showed that spends crypto on the attacker's behalf; closed silently instead and wrote down why. Teaches: evidence over plan-adherence. (L8)

5. The harness that lied

pkill pattern matched the proxy's own argv; unquoted zsh $args made four guardrail tests pass vacuously. Teaches: test infrastructure is untested code. (L7/L8/L10)

30-Second Answers

The compressed versions — when the interviewer wants the shape, not the essay:

PromptThe 30-second answer
Circuit breakerThree states; failures open it, a timer half-opens it, successes close it; asymmetric thresholds prevent flapping; backoff doubles on failed recovery.
Consistent hashingHash servers onto a ring many times; a key maps to the next point clockwise; adding a server moves ~1/N of keys instead of nearly all (modulo's failure).
Token bucketCapacity = burst, refill = rate; take one per request; lazy refill on access needs no timer; per-key buckets shard to avoid a global lock.
Cache stampedePopular key expires, N requests all miss at once; fixes: request coalescing (one fetch, N-1 waiters), stale-while-revalidate, TTL jitter.
Graceful shutdownCatch signal, close listener, drain in-flight with Connection: close, hard deadline, exit; the deploy must not be hostage to a hung client.
Hot reloadBuild the new config completely off to the side; validate wholesale; swap one pointer; in-flight keeps its snapshot; invalid input changes nothing.
Anomaly scoringRules add points, block at a threshold: one weak signal is noise, three together are a conviction — false-positive control is the product.
epoll vs selectselect scans all N fds every call (O(n)); epoll returns only ready ones (O(ready)) — idle connections become free, which dissolved C10K.
Data/control planeData plane serves traffic with a simple, crash-proof config-swap interface; control plane computes and pushes the config; they fail independently.
Observability pillarsMetrics aggregate (cheap, queryable over months), logs record events (one JSON line per request), traces time stages; request-id stitches them.
